# 計画作成時間の計測手順

抄録の「無作為に抽出した10件で、計画作成時間を手入力とアプリでそれぞれ計測した」の手順を定める。

## 条件

| 項目 | 内容 |
|---|---|
| 対象 | 本格運用2年間（2024-09-01～2026-08-31）に作成された計画書から無作為に10件 |
| 入力する人 | 医療秘書1名 |
| 手入力 | 公開Excel様式に空白から入力する。初回は `2024e9-1.xlsx`、継続は `2024e9-2.xlsx` |
| アプリ | 本番DBのコピーを使う検証用環境で作成する |
| 計測する人 | 入力する人とは別の1名。画面録画も行う |

- 2026年6月以降の計画書が選ばれても、手入力には2024様式を使う。2026様式 `2026e9.xlsx` は使わない。

## 1. 抽出

1. 本番の `ldtp_app.db` を院内の作業用フォルダにコピーする。
2. 計測日の日付などをシードに決めて、記録しておく。
3. 次のコマンドで抽出する。DBは読み取り専用で開く。結果は画面に出すだけで、ファイルには保存しない。

   ```bash
   python sample_plans.py <コピーしたDB> <シード>
   ```

4. 表示された母集団の件数が33,498件と一致するか確かめる。違えば、抽出の条件を見直す。
5. 結果を記録表に貼る。出力に患者IDが含まれるので、リポジトリにはコミットしない。
6. 初回と継続の内訳が、母集団の割合からかけ離れていないか確かめる。継続は約85%なので、10件中8～9件が目安になる。
7. 除外基準は「記載が途中の計画書」だけにする。除外したら、その理由を記録する。補充は、シードを変えずに件数を11にして実行し、11番目を使う。

## 2. 準備

1. 抽出した10件それぞれについて、計画書の内容をアプリから印刷し、正解シートにする。
2. 検証用のアプリを本番とは別のフォルダに用意し、コピーしたDBを置く。
   - `config.ini` の `patient_data` は、検証用の pat.csv を指すようにする。
   - pat.csv には、対象患者の患者IDを入れる。氏名などはダミーで構わない。
   - 計測中に pat.csv を消すとアプリが終了するので、消さない。
3. 継続の計画書は、前回の計画書がDBに残っているので、アプリで新規作成すると前回の内容が複製される。初回の計画書は、テンプレートを適用して作成する。
4. 10件を無作為に5件ずつに分け、半分は「手入力→アプリ」、残りは「アプリ→手入力」の順にする。2つの方法は別の日に計測する。
5. 本番の前に、10件以外の計画書で、両方の方法を1回ずつ練習する。

## 3. 計測

| 方法 | 開始 | 終了 |
|---|---|---|
| 手入力 | 空白の様式を開いた状態で、計測者が合図した時点 | 入力を終えて保存した時点 |
| アプリ | ホーム画面で、患者IDを入力する前に計測者が合図した時点 | 計画書が生成され、Excelで開いた時点 |

- 両方とも、印刷と署名は含めない。
- 計測中に手が止まったときも、時計は止めない。止まった理由を備考に書く。
- 終わったら、出力した計画書を正解シートと照らし合わせ、入力誤りの数を数える。

## 4. 記録表の列

`症例No / id / 作成日 / 主病名 / シート名 / 初回・継続 / 前回からの変更項目数 / 測定順 / 手入力の秒数 / アプリの秒数 / 手入力の誤り数 / アプリの誤り数 / 測定日 / 備考`

## 5. 集計

- 手入力とアプリの作成時間を、それぞれ中央値と範囲で示す。
- 同じ10件で比べるので、Wilcoxon符号順位検定で差を確かめる。
- 削減時間の推計は、差の中央値に延べ33,498件を掛けて計算し直す。

## 6. 抄録への反映

方法の文を、次のように改める。

> 無作為に抽出した計画書10件を、医療秘書1名が公開Excel様式への手入力とアプリでそれぞれ作成し、作成時間を計測した。

入力したのは医師ではなく医療秘書なので、医師が入力したときの時間とは異なる場合がある。この点を考察の限界に書く。
