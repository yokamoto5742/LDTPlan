# 生活習慣病療養計画書作成アプリ LDTPlan

**外来の流れを止めずに生活習慣病療養計画書を作成する**ためのWindowsデスクトップアプリです。患者ごとの計画内容をSQLiteに記録し、Excelテンプレートでバーコード付きの計画書を生成します。

## LDTPlan 開発の経緯

このアプリの導入前は、医師が生活習慣病療養計画書を**Excelファイルのテンプレートに毎回手入力**で作成していました。

- ファイルに患者ごとのデータが残らない → **毎回ゼロから作り直し**
- 計画内容は患者ごとにほぼ同じ → **同じ入力作業の繰り返し**

このアプリは「**一度作成した計画書を保存し、2回目以降は前回の計画書をコピーして修正する**」ことで、繰り返し作業を解消するのがねらいです。

## 特徴

- **患者ごとの計画を保存** — 作成した計画書の内容をSQLiteに保存。次回受診時は患者IDで呼び出し、変わった項目だけ直して素早く発行できる。
- **疾病別テンプレート** — 主病名・目標数値別にデフォルト値をDB管理。テンプレートで入力を最小化する。
- **Excelテンプレートをそのまま活用** — 一般公開されている療養計画書のExcelテンプレートを使用。印刷・電子カルテへのPDF保存といった後処理はExcelマクロ側にボタンで足せる（[設計ノート参照](#1-pdf直接生成ではなくexcelxlsmを採用した理由)）。
- **バーコードを画像として焼き込み** — Excelアドイン型のバーコードに依存しない。アドインはExcelのバージョンによって表示できなくなるリスクがあるため、ZXing.Netで生成したCode128画像をセルに配置する（[設計ノート参照](#3-バーコードはアドインではなく画像として配置)）。
- **サーバーレスなSQLite** — DBは実体がファイル1つ。院内共有ファイルサーバーに置いて各電子カルテ端末から参照できる（[設計ノート参照](#2-postgresqlではなくsqliteを使い続ける理由)）。
- **pat.csv の自動監視** — 電子カルテが出力する患者データCSVを FileSystemWatcher で監視し、削除されたらアプリを自動終了する。

## 動作環境

- Windows 10 64bit 以上
- メモリ 4GB 以上推奨

## インストール方法

1. リポジトリをクローン
   ```bash
   git clone https://github.com/yokamoto5742/LDTPlan.git
   cd LDTPlan
   ```

2. `config.ini` を自院の環境に合わせて編集（特にテンプレートパス・出力パス・pat.csvのパス。詳細は[設定](#設定configini)）

3. ビルドして起動
   ```bash
   dotnet run --project LDTPlan.csproj
   ```
   起動時に pat.csv の存在を確認し、データベースを自動初期化します。

4. 配布用にビルドする場合
   ```bash
   dotnet publish LDTPlan.csproj -c Release
   ```
   出力先の `LDTPlan.exe`・`e_sqlite3.dll`・`config.ini` を配布します（3ファイルとも同じディレクトリに置く）。発行時にこの3ファイルは `C:\Shinseikai\LDTPlan` へ自動コピーされます。

## 使い方

### 基本的なワークフロー

1. **起動** — `LDTPlan.exe` を実行
2. **患者を選択** — 患者IDを入力すると、pat.csv から患者情報が自動読み込みされ、その患者の計画書一覧が表示される
3. **計画書を作成** — 「新規作成」→ 主病名を選択 → シート名（目標数値別）を選択 → 目標値・食事/運動処方などを入力。テンプレートのデフォルト値が自動適用されるので、変更点だけ直す。2回目以降は「前回計画コピー」で前回内容を複製してから一覧の行クリックで編集する
4. **文書を生成** — 「新規登録して印刷」で xlsm を生成してExcelで開く
   - ファイル名: `{患者ID}{文書番号}{診療科ID}{医師ID}{日付}{時刻}.xlsm`
   - 出力先: `config.ini` の `output_path`
   - バーコードを初回用・継続用シートの B2 セルに自動挿入

### テンプレート編集

「テンプレート編集」→ 主病名とシート名を選択 → デフォルト値を編集 → 「テンプレート保存」

### データのエクスポート・インポート

「設定」画面のCSV出力で患者情報を一括出力（出力先は `config.ini` の `export_folder`）。CSV取込で `patient_info_*.csv` を読み戻せます。

## 設定（config.ini）

exeと同じディレクトリの `config.ini` で全パス・サイズ設定を一元管理します。

```ini
[Database]
db_url = sqlite:///ldtp_app.db

[settings]
window_width = 1050
window_height = 600

[Paths]
; template_path: 計画書テンプレート(xlsm) / output_path: 生成文書の出力先
template_path = C:\Shinseikai\LDTPapp\LDTPform.xlsm
output_path   = C:\Shinseikai\LDTPapp\temp

[FilePaths]
; patient_data: 電子カルテが出力する患者CSV
patient_data  = C:\InnoKarte\pat.csv
export_folder = C:\Shinseikai\LDTPapp\export_data
manual_pdf    = C:\Shinseikai\LDTPapp\LDTPapp_manual.pdf

[Barcode]
; 画像サイズ(px)・余白・挿入セル
image_width    = 200
image_height   = 30
quiet_zone     = 1
image_position = B2
```

## 設計ノート

### 1. PDF直接生成ではなくExcel(xlsm)を採用した理由

- 印刷や「電子カルテへPDF保存」といった**後処理を、Excelマクロにボタンとして簡単に追加できる**。PDFを直接吐く設計だと、この拡張が難しくなる。
- 療養計画書の**テンプレートがExcel形式で一般公開されており**、それをそのまま使うのが最短だった。
- VBAマクロは ClosedXML がxlsm保存時に自動保持する。

### 2. PostgreSQLではなくSQLiteを使い続ける理由

PostgreSQLはDBサーバーの構築・運用が必要になる。SQLiteは実体がファイル1つなので、**院内共有ファイルサーバーに置いて各電子カルテ端末から参照する**運用が、サーバーを立てずに実現できる。院内ツールの配布・保守コストを最小化する判断。SQLiteのバックアップはファイルサーバー側で行う。

### 3. バーコードはアドインではなく画像として配置

Excelアドイン型のバーコードツール（特に古いもの）は、**Excel本体の更新で新バージョンに対応できず、バーコードが表示されなくなる**ことがある。これを避けるため、ZXing.Net（Code128）で生成した画像を ClosedXML でセルに貼り付ける方式にしている。Excelのバージョンに依存しないのが利点。

## アーキテクチャ

三層構造:

| 層 | ディレクトリ | 役割 |
|----|-------------|------|
| UI層 | `Forms/` | WinFormsフォーム・イベントハンドラ |
| サービス層 | `Services/` | Excel生成・患者操作・CSV入出力・ファイル監視などのビジネスロジック |
| データ層 | `Models/` `Data/` | EF Coreエンティティ・DbContext・初期データ投入 |

計画書生成の流れ:

```
入力情報 → DBに登録 → TreatmentPlanGenerator.GeneratePlan()
  → テンプレート読み込み（ClosedXML, VBAマクロ保持）
  → PopulateCommonSheet() で共通情報シートへデータ入力
  → バーコード生成（ZXing.Net）→ 初回用・継続用シートのB2セルへ画像配置
  → 初回用/継続用シートを選択（同一患者の先行レコード有無で判定）
  → xlsm を出力してExcelで開く
```

## トラブルシューティング

| 症状                | 原因                           | 対処                                             |
| ----------------- | ---------------------------- | ---------------------------------------------- |
| 起動してもウィンドウが表示されない | pat.csv が存在しない、またはパス誤り       | `config.ini` の `FilePaths.patient_data` を確認・修正 |
| テンプレート読み込みエラー     | テンプレートのxlsmが他で開かれている／破損      | Excelを閉じる、ファイル権限とテンプレートを確認                     |
| バーコード生成失敗         | 患者ID・文書番号が不正、または出力先に書き込み権限なし | 出力パスの権限と `config.ini` の `[Barcode]` 設定を確認      |
| データベース接続エラー       | `ldtp_app.db` の破損、ディスク容量不足   | DBファイルを削除して再初期化、ディスク容量を確認                      |
