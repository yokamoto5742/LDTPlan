description: コミットメッセージの形式とブランチ運用
---

`✨ feat`, `🐛 fix`, `📝 docs`, `♻️ refactor`, `✅ test` プレフィックスを使用し、変更内容と理由を日本語で記述する。

## ブランチ運用

- 個人開発のためブランチは切らず、`master` を直接編集してローカルにコミットする。
- `git push` はユーザーがコミット内容を確認してからプッシュする。
- プッシュ前のコミットであっても、指示なく `git commit --amend` / `git rebase` / `git reset` で履歴を書き換えない。修正は新しいコミットで行う。

## コミット実行時の注意

- Bash ツールのコマンドに日本語を直接含めると文字化けして失敗する(ヒアドキュメントも不可)。
- コミットメッセージは Write ツールでスクラッチパッドのファイルに書き、`git commit -F <ファイル>` で渡す。

## 変更後の作業

- コードやドキュメントを変更したら、必ずコミットまで行う。
- コードを変更した場合は、コミット前に次も行う。
  - `docs/CHANGELOG.md` を更新する。CHANGELOG.mdの記述はできるだけ()を使わない。
  - アプリケーションのバージョンを上げる。`docs/CHANGELOG.md` のバージョンとそろえる。
