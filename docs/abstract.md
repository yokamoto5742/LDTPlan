# 日本メディカルAI学会学術集会 一般演題 抄録案

## 演題名案

- 案1: 開発経験のない医療秘書がAIコーディングで開発・再構築した生活習慣病療養計画書作成アプリ ― 延べ3.3万件の運用実績から
- 案2: 現場の言語化力×AIコーディング：制度改定に2か月で即応した院内アプリの開発と2年間の運用

## 構成の意図

| 聴衆（主に医師）の問い | 抄録で答える箇所 |
|---|---|
| 自院でも作れるのか？ | 【方法】開発経験のない医療秘書がAIで開発 |
| 臨床の時間は戻るのか？ | 【結果】延べ33,498件・継続作成率・変更項目数・作成時間 |
| 作った後に責任を持てるのか？ | 【結果】改修2～3日・1週間での再構築／【考察】設計と運用があれば作り直せる |

結論は「AIがあれば誰でも作れる」ではなく、「**現場の運用を言葉にでき、実際に使って評価できる人がいれば作れる**」とする。

## 抄録本文

【背景】2024年度診療報酬改定で生活習慣病管理料（Ⅱ）の算定に療養計画書が必要となった。公開されたExcel様式は患者データが残らず作成負担が大きく、外注では改定に間に合わなかった。

【目的】開発経験のない医療秘書がAIコーディングで療養計画書アプリを開発し、運用データから有用性を検討する。

【方法】医療秘書が内科医の意見を基に画面と要件を言語化し、ClaudeでPython（Flet）のコードを生成した。計画を患者ごとに保存し、継続時は前回内容を複製し差分のみ修正する方式とした。情報システム部門と連携し電子カルテからの患者情報取得とバーコード付きExcel出力を実装した。本格運用後2年間の延べ33,498件で利用推移、更新間隔、変更項目を集計し、無作為抽出10件で作成時間を計測した。倫理審査の承認を得た。

【結果】2024年6月に試行、9月に本格運用した。患者5,134名、医師30名が利用し、月約1,400件で24か月安定した。継続作成率は95.8%、更新間隔は中央値91日で88.8%が120日以内だった。変更は平均0.5項目で74.6%は無変更、主な変更は目標達成状況の評価（15.7%）だった。作成時間は手入力の約2～3分から約20秒に短縮し、2年間で約930～1,490時間の削減と推計した。改修要望は2～3日で反映した。運用2年後、起動遅延とFlet更新への追従困難に対しClaude Codeで約1週間でC#/.NETに再構築し、起動時間は約10秒から約2秒となった。

【考察】前回複製方式で医師の入力は達成状況の評価と必要な修正に集中した。AIはコード記述の障壁を下げたが、運用に即した要件の言語化、実使用による評価、情報システム部門との連携が重要であった。設計が明確であれば短期間で再構築できた。

【結論】AIコーディングにより開発経験のない医療秘書が制度改定に即応した院内アプリを開発・運用・再構築し、医師の文書作成を効率化した。

## 追加した集計値の定義（export.csv、2024-09-01～2026-08-31）

| 抄録の記述 | 値と定義 |
|---|---|
| 月約1,400件で24か月安定 | 月別件数 1,209～1,617件、平均1,396件 |
| 更新間隔 中央値91日 | 同一患者で連続する2件の間隔、29,027組。IQR 70～98日 |
| 88.8%が120日以内 | 間隔120日以内の割合、25,774 / 29,027組 |
| 主な変更は目標達成状況の評価 | 項目別の変更率は目標達成状況15.7%、がん検診7.1%、日常の活動量4.1%、ほかは3%以下 |

抄録に入れなかった値: 月間利用医師数はその月に1件以上作成した医師数で最小18名、最終月26名。初期3か月に作成した患者3,742名のうち85.6%が2026年3月以降も作成継続。自由記載欄の入力率は食事3.3%、運動7.7%。

## 留意事項

- 計画書データの集計は診療情報の二次利用にあたるため、院内の倫理審査またはオプトアウトの手続きを抄録提出前に確認する。
- 利益相反（COI）はなし。
