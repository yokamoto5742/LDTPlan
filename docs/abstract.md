# 日本メディカルAI学会学術集会 一般演題 抄録案

## 演題名案

- 案1: 開発経験のない医療秘書がAIコーディングで開発・再構築した生活習慣病療養計画書作成アプリ ― 延べ4万件の運用実績から
- 案2: 現場の言語化力×AIコーディング：制度改定に2か月で即応した院内アプリの開発と2年半の運用

## 構成の意図

| 聴衆（主に医師）の問い | 抄録で答える箇所 |
|---|---|
| 自院でも作れるのか？ | 【方法】開発経験のない医療秘書がAIで開発 |
| 臨床の時間は戻るのか？ | 【結果】延べ約4万件・継続作成率・変更項目数・作成時間 |
| 作った後に責任を持てるのか？ | 【結果】改修2～3日・1週間での再構築／【考察】設計と運用があれば作り直せる |
| 何が成功の条件か？ | 【考察】要件の言語化・実使用での評価・院内連携 |

結論は「AIがあれば誰でも作れる」ではなく、「**現場の運用を言葉にでき、実際に使って評価できる人がいれば作れる**」とする。

## 抄録本文

【目的】2024年度診療報酬改定で生活習慣病管理料（Ⅱ）の算定に療養計画書の発行が必要となった。公開されたExcel様式は患者ごとにデータが残らず、外来で毎回ゼロから作成する負担が大きい。外注では改定に間に合わないため、開発経験のない医療秘書がAIコーディングで作成支援アプリを開発し、その有用性を検討した。

【方法】医療秘書が医師の意見を基に画面レイアウトと要件を言語化し、Claude（後にClaude Code）にコードを生成させた。計画内容を患者ID単位でSQLiteに保存し、再診時は前回内容を複製して差分のみ修正する方式とした。電子カルテ出力CSVからの患者情報自動取得、カルテ切替時の自動終了、バーコード付きExcel出力を実装した。運用約2年半の計画書延べ約4万件で、継続作成の割合と前回からの変更項目数を集計した。

【結果】プロトタイプはExcelで描いた画面と簡易な要件から約8割が一度で生成され、2024年6月に運用を開始した。残り2割の電子カルテ連携等の調整に時間を要した。延べ約4万件のうち継続作成は○%、変更項目は中央値○項目で、1件の作成時間はExcel手入力の約2～3分から約○秒に短縮した。改修要望は2～3日で反映した。起動の遅延とフレームワーク更新への追従困難に対し、約1週間でC#/.NETに再構築し、起動時間は約10秒から○秒に短縮した。

【考察】AIはコード記述の障壁を下げたが、成否を分けたのは現場の運用に即した要件の言語化、実使用による評価、院内関係部門との連携であった。診療を支える医療秘書が開発を担うことで、迅速な改修が可能となった。また設計と運用が明確であれば、保守が困難になっても汎用的な言語で短期間に再構築できた。

【結論】AIコーディングにより、開発経験のない医療秘書が制度改定に即応した院内アプリを開発・運用・再構築できた。現場を知る非エンジニアとAIの協働は、医療現場の業務改善に有用である。

## 提出前に埋める数値（○の箇所）

| 項目 | 算出方法 |
|---|---|
| 継続作成の割合 | 全件のうち作成回数が2以上の件数の割合 |
| 変更項目数の中央値 | 同一患者で連続する2件の計画を項目ごとに比較し、値が異なる項目数を数える。日付・作成回数など自動で変わる項目は除く |
| 作成時間 | Excel手入力とアプリで各5～10件をストップウォッチで実測。初回作成と継続作成を分けて測る |
| C#版の起動時間 | 同じ端末・同じDBでPython版とC#版の起動時間を各数回測る |

字数に余裕があれば、患者実数・利用医師数・1人あたりの平均作成回数を【結果】に加える。

## 留意事項

- 計画書データの集計は診療情報の二次利用にあたるため、院内の倫理審査またはオプトアウトの手続きを抄録提出前に確認する。
- 作成時間は現時点では体感値のため、実測するまでは「約30秒の見込み」と書かない。
- 利益相反（COI）の開示が必要かどうかを学会規定で確認する。
